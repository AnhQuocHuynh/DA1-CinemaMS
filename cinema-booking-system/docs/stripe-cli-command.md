# Stripe CLI Webhook Forwarding Guide

This guide explains how to forward Stripe webhook events to your local environment, what the command does, when to run it, and how to configure the Stripe webhook secret for the first time.

---

## 1. The Stripe CLI Command

Run this command in your terminal while developing locally:

```bash
stripe listen --forward-to http://localhost:5000/api/payments/callback/stripe
```

> [!NOTE]
> The target URL routes through the **Yarp API Gateway** (`http://localhost:5000`), which proxies incoming webhook requests to `payment-service` at `POST /api/payments/callback/stripe`.

---

## 2. What This Command Does

1. **Creates a Secure WebSocket Tunnel**: Connects your local workstation to Stripe's test event stream via WebSocket.
2. **Forwards Webhook Events**: Captures real-time Stripe events generated by test checkouts (e.g., `checkout.session.completed`, `payment_intent.payment_failed`, `charge.succeeded`) and delivers them to your local endpoint `http://localhost:5000/api/payments/callback/stripe`.
3. **Signs Payloads Locally**: Stripe CLI signs each forwarded request with a unique webhook signing secret and sends it in the `Stripe-Signature` header.
4. **Enables Backend Verification**: Allows [StripeGateway.cs](file:///c:/DoAn1/DA1-CinemaMS/cinema-booking-system/backend/services/payment-service/PaymentService.Infrastructure/Gateways/StripeGateway.cs) to cryptographically verify payload authenticity before completing payment sagas and dispatching RabbitMQ events (`payment.completed`).

---

## 3. When to Run It

Run this command whenever you are **developing or testing online Stripe payments locally**:

- **Customer Checkout**: When testing online ticket booking from the customer frontend (`http://localhost:3000`).
- **Counter Booking**: When testing staff-assisted or member bookings using Stripe as the payment method.
- **Saga Orchestration Testing**: When verifying the end-to-end payment lifecycle:
  `Stripe Checkout` $\rightarrow$ `Webhook Callback` $\rightarrow$ `PaymentStateMachine` $\rightarrow$ `RabbitMQ (payment.completed)` $\rightarrow$ `booking-service (PAID)` $\rightarrow$ `showtime-service (BOOKED)`.
- **Payment Failure Handling**: When simulating declined cards or cancellations to test compensating transactions (`payment.failed` and seat release).

> [!IMPORTANT]
> Because Stripe servers cannot communicate with `localhost` over the public internet, local checkout webhooks **will fail or hang in PENDING status** unless this listener tunnel is actively running.

## 4. How to Set the Environment Variable for the First Time

### Step 1: Install & Authenticate Stripe CLI

If not already installed:
- **Windows (Winget)**:
  ```powershell
  winget install Stripe.StripeCLI
  ```
- **Windows (Scoop)**:
  ```powershell
  scoop bucket add stripe https://github.com/stripe/stripe-cli.git
  scoop install stripe
  ```
- **macOS (Homebrew)**:
  ```bash
  brew install stripe/stripe-cli/stripe
  ```

Authenticate your CLI with your Stripe test account:
```bash
stripe login
```
Follow the browser prompt to authorize access.

---

### Step 2: Start the Listener & Copy the Signing Secret

Execute the forwarding command:
```bash
stripe listen --forward-to http://localhost:5000/api/payments/callback/stripe
```

Upon launching, the terminal will display output similar to:
```text
> Ready! You are using the Stripe CLI in testmode.
> Your webhook signing secret is whsec_1234567890abcdef1234567890abcdef... (^C to quit)
```

**Copy the secret key** starting with `whsec_`.

---

### Step 3: Configure the Webhook Secret in `payment-service`

Choose one of the configuration methods below to supply `Stripe:WebhookSecret`:

#### Option A: .NET User Secrets (Recommended for Local Dev)
Run this command from the repository root:
```bash
dotnet user-secrets set "Stripe:WebhookSecret" "whsec_YOUR_COPIED_SECRET" --project cinema-booking-system/backend/services/payment-service/PaymentService.Presentation
```

#### Option B: `appsettings.Development.json`
Update [appsettings.Development.json](file:///c:/DoAn1/DA1-CinemaMS/cinema-booking-system/backend/services/payment-service/PaymentService.Presentation/appsettings.Development.json):
```json
{
  "Stripe": {
    "SecretKey": "sk_test_YOUR_STRIPE_TEST_SECRET_KEY",
    "PublishableKey": "pk_test_YOUR_STRIPE_TEST_PUBLISHABLE_KEY",
    "WebhookSecret": "whsec_YOUR_COPIED_SECRET"
  }
}
```

#### Option C: Shell Environment Variable
- **PowerShell**:
  ```powershell
  $env:Stripe__WebhookSecret="whsec_YOUR_COPIED_SECRET"
  ```
- **Windows Command Prompt (CMD)**:
  ```cmd
  set Stripe__WebhookSecret=whsec_YOUR_COPIED_SECRET
  ```
- **Bash / Zsh (Linux/macOS)**:
  ```bash
  export Stripe__WebhookSecret="whsec_YOUR_COPIED_SECRET"
  ```

#### Option D: Docker Compose (`.env`)
If running `payment-service` inside Docker:
```env
Stripe__WebhookSecret=whsec_YOUR_COPIED_SECRET
```

---

### Step 4: Restart `payment-service`

Restart the payment service so it picks up the newly configured `Stripe:WebhookSecret` value.

---

### Step 5: Verify the Setup

In a separate terminal window, trigger a test Stripe webhook event:
```bash
stripe trigger checkout.session.completed
```

Check your listener terminal and backend logs:
- **Stripe CLI Terminal**: Should log `--> POST http://localhost:5000/api/payments/callback/stripe [200 OK]`.
- **Payment Service Logs**: Should log `Stripe webhook event received: checkout.session.completed`.
